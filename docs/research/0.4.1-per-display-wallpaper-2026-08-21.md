# 0.4.1 按显示器壁纸分配 — 调研 (2026-08-21)

> 范围：`manual` 下每屏可不同，不做轮播。来源 `43bf8831` 子代理报告精炼。

## 1. 现状数据流

- **存储**：`gallery/index.json` 0600（条目池，去重 `sha256:contentKey`）+ `<shortId>/wallpaper` 0644 + `$DATA_HOME/mip-paper/wallpaper` 全局活指针 + `wallpapers/<displayKey>/` KDE 缓存 + `colors/by-content/<digest>.json` 按 `contentKey` 缓存
- **发布链**：`bin/mip-paper wallpaper set/gallery set id` → `scripts/wallpaper-gallery.mjs` → `wallpaper` 单文件 → `main.mjs onWallpaperImported() -> wallpaperSync.setMode('manual') -> reconcile()`；Settings 经 `window-manager.mjs SETTINGS_GALLERY_SET_ACTIVE_CHANNEL -> gallerySetActive + saveConfig({mode:manual}) -> runtimeCoordinator -> wallpaperSync`；`main bootstrap` 经 `colorService.wallpaperChanged(displayId)->wallpaperTransactions.set(displayId)->manager.updateWallpaper(displayId)` 按屏定向 `WALLPAPER_UPDATED_CHANNEL`，但 `manual` 分支对所有屏发布同一 `inspected(manualWallpaper)`。
- **UI**：`settings.mjs` 画廊用 `primary bounds` 估 `coverInfoFor`，无 display selector；`main getSettingsState()` 已返回 `displays`，未回传 `assignments`。

## 2. 三方案对比

| 方案 | 存储 | 热加载 | 配置整洁 | 迁移 |
| --- | --- | --- | --- | --- |
| A `config.assignments` | `config.json` | 现成 | 污染 diff | 中 |
| **B 独立 JSON** `gallery/display-assignments.json` ⭐ | 独立 0600 原子 | 新增 watcher ~20 行 | 干净 | 低 |
| C 物化 `wallpapers/<id>/wallpaper` | 每屏 copy | 现成 | 中 | 高 |

推荐 **B1 独立 assignments JSON + 不物化直指 gallery 文件** + `config.wallpaper.mode` 不变。

## 3. 推荐 Schema

```json
// gallery/display-assignments.json 0600, 0700 目录
{
  "version": 1,
  "fallback": "sha256:abc... | null",
  "assignments": { "123": "sha256:def...", "456": "sha256:ghi..." },
  "updatedAt": "ISO"
}
// config.json 仅可选旗标
"wallpaper": { "mode":"kde|manual", "fit":"cover", "crossfadeMs":420, "perDisplay": false }
```

- `displayId = String(screen.getAllDisplays().id)`，与 `window-manager`/`colorService` 键一致
- `fallback` 即“全部”，`assignments[displayId]` 优先，缺失回退 `fallback ?? legacy wallpaperPath ?? defaultWallpaper`
- `fit/crossfadeMs` 0.4.1 保持全局

新增模块 `src/wallpaper-assignments.mjs`:

```js
export function assignmentsPath(env,homedir)
export async function readAssignments(env,homedir) // ENOENT→{version:1,assignments:{},fallback:null}
export async function writeAssignmentsAtomic(env,homedir,file) // tmp→rename 0600
export async function setAssignment(displayId|'fallback', contentKey|null)
export async function resolveContentKey(displayId)
```

## 4. 关键细节

- **displayId 稳定性**：Wayland 下 `Chromium id` 非稳定映射 `drm connector`，重排序会变；对策：存 `String(id)` + UI 显示 `x,y WxH scale`，`reconcile` 时 orphan 条目置灰，用户可迁移；后续可考虑 `output name DP-1` 但需 `kwin/main.js` 改动，不在 0.4.1。
- **去重**：同 `contentKey` 两屏共享色缓存 `colors/by-content`，`submitWallpaperAccent` 按 `contentKey` 广播正确；`pruneGallery({keepKeys})` 不得清被分配条目；`removeFromGallery` 需回退 assignments。
- **Fallback 链**：`key = assignments[displayId] ?? fallback ?? (await getActiveContentKey())`，缺文件回退 default。
- **色服**：`colorService.records Map<displayId>` 已按屏，无改动，仅需 `main onUpdate` 传入 per-display `contentKey`。
- **热加载**：`assignmentsWatcher` debounce 150ms → `wallpaperSync.reconcile()`，与 `configWatcher` 的 `setMode` 串行（`runtimeCoordinator generation` 防旧 publish）。
